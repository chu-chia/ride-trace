# 部署（讓手機和老師用網址連進來）

## 目前的正式部署（2026-11-22 起）

```
Mac（開發）── git push main ──> GitHub chu-chia/ride-trace（私人）
                                   │  GitHub Actions：.github/workflows/ci.yml
                                   │  （Python／JS 語法、起 redis＋api＋worker 跑 scripts/ci/smoke.py）
                                   ▼
Windows node（正式機，Redis 正本）每分鐘 scripts/windows/autodeploy.ps1：
  有新 commit 且 CI 通過 → git reset --hard → 改到後端才 docker compose up -d --build
  CI 沒過 → 不部署，設定頁紅字「最新版沒通過檢查」
                                   │  tailscale serve 8443 → 8750
                                   ▼
手機：https://node.tail866fc3.ts.net:8443（設定頁最下面看得到目前版本）
```

- 推完約 1～2 分鐘上線（CI 約 45 秒＋下一次輪詢）；只改 `web/` 不用重建。
- Windows 的設定、換 token、常見問題：`scripts/windows/README.md`。
- 下面 1～6 節是通用做法（在任何一台主機自己架）。


手機網頁定位一定要 HTTPS。最省事的做法：系統照樣跑在自己的 Mac（或任何一台 Linux 主機）上，用 **Tailscale** 開一個固定的 `https://<機器名>.<tailnet>.ts.net` 網址，不用開 port、不用固定 IP，憑證自動處理。

## 1. 主機上把服務跑起來

```bash
cd ~/development/ride-trace
cp .env.example .env            # 填 SIM_BOT_PASSWORD、ADMIN_USERS
docker compose up -d --build
curl -s localhost:8750/api/health   # {"ok":true,"redis":"8.x"}
```

第一次啟動 Valhalla 會下載台灣路網並建立，約 3～30 分鐘；之後資料在 `data/valhalla/`，重開很快。

## 2. 只給自己和隊友用：`tailscale serve`

裝了 Tailscale、登入同一個 tailnet 的裝置才連得到（隊友的手機也要裝 Tailscale）。

```bash
brew install tailscale        # 或從官網裝 App
tailscale up
tailscale serve --bg 8750     # https://<機器名>.<tailnet>.ts.net → localhost:8750
tailscale serve status
```

> 這台電腦的 443 已經給其他專案用時，改開別的 HTTPS port（Tailscale 只允許 443、8443、10000）：`tailscale serve --bg --https=8443 http://127.0.0.1:8750`，網址變成 `https://<機器名>.<tailnet>.ts.net:8443`；關掉用 `tailscale serve --https=8443 off`。

## 3. 給老師或任何人直接打開：`tailscale funnel`

Funnel 會把網址公開到網際網路（一樣是 HTTPS），繳交時貼這個網址。

```bash
tailscale funnel --bg 8750
tailscale funnel status       # 印出公開網址
```

> 公開之前：
> - 登入頁可以自己註冊帳號；展示期間如果不想讓陌生人註冊，可以展示完就 `tailscale funnel --bg off`。
> - 管理後台只有 `ADMIN_USERS` 裡的帳號看得到。
> - 足跡、點亮鄉鎮、熱力圖都只有本人看得到。

## 4. 手機設定

- **網頁**：用手機打開上面的 https 網址登入，進行程頁「回報」分頁開網頁定位（畫面要保持開著）。
- **Traccar Client（建議）**：伺服器網址填 `https://<網址>/osmand`，裝置 ID 填行程頁「回報」分頁顯示的那一組；頻率 2～5 秒。原生 App 可以在背景回報，螢幕關掉也沒關係。

## 5. 資料保存與備份

- Redis 開了 AOF（每秒寫入）和 RDB（300 秒內有 10 次變更就存），資料在 Docker 的 named volume `redis-data`，`docker compose down` 不會刪掉（`down -v` 才會）。
- 手動備份：`docker exec qiji-redis-1 redis-cli BGSAVE`，再 `docker cp qiji-redis-1:/data/dump.rdb ./data/backup/`。
- 繳交用的匯出見 `docs/繳交清單.md`。

## 6. 放到雲端 VM（選用）

任何有 Docker 的 Linux VM（GCP e2-medium、AWS t3.medium 以上，Valhalla 建路網時要 4 GB 記憶體）都可以：把專案和 `data/valhalla/` 複製過去，`docker compose up -d`，再用 Tailscale Funnel 或 Caddy＋網域開 HTTPS。個人足跡（`data/` 和 Redis 裡的 footprint）要不要放上雲端由自己決定。
