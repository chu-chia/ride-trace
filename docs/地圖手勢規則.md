# 地圖手勢規則 v2

> 狀態：**已實作**（2026-11-18）。使用者決定「全部照 v2」，第 20 條改成行程頁、戰情室都 10 秒。
> 程式：`web/assets/gestures.js`（共用手勢判斷）、`mapbase.js`（跟隨讓路與平滑接回）、`trip.js`／`replay.js`／`war.js`（各頁狀態）。
> 適用頁面：行程頁 `/trip`、回放 `/replay`、戰情室 `/war`（規劃 `/plan`、足跡 `/footprint` 沒有跟隨，照地圖預設操作）。

## 業界共通的做法（整理自參考資料，見文末）

1. **鏡頭只有三種狀態**：自由（Idle）、跟隨（Following）、全隊總覽（Overview）。Mapbox Navigation SDK 的 `NavigationCamera` 就是這三態；手勢只會讓鏡頭「掉到自由」，不會跳到別的狀態。
2. **「移動位置」才算離開跟隨，「縮放／旋轉／傾斜」不算**。Google 地圖導航、Apple 地圖、MapLibre Native 的 `LocationComponent`（`trackingGesturesManagement`）都是這樣：拖曳超過門檻才斷開；雙指縮放以被跟隨的人為中心，人一直在畫面中間。
3. **拖曳要超過門檻才斷開**：MapLibre Native 有 `trackingInitialMoveThreshold`（單指）與 `trackingMultiFingerMoveThreshold`（雙指縮放時手指中點的位移），避免手指一碰就斷開。
4. **斷開後按鈕變「外框」狀態**，點一下回去（MapLibre GL JS `GeolocateControl` 的 `ACTIVE_LOCK → BACKGROUND`；Google 地圖的「重新置中」）。不另外跳出提示文字。
5. **自動回去是可選設定**：OsmAnd 導航時有「自動置中地圖」，可選 永不／5／10／15／…／90 秒，每次再動地圖就重新計時。一般地圖 App（Google、Apple）瀏覽時不會自動拉回，只有導航中會。
6. **總覽模式碰了就交給使用者**：Mapbox Navigation SDK 在 Overview 下任何手勢都轉 Idle。

## 名詞

- **跟隨某人**：點騎士標記、點隊員表、或按「跟我」。鏡頭每一格把那個人放在畫面中間。
- **全隊**：按「全隊」。鏡頭自動框住所有在線騎士。
- **自由**：沒有跟隨，鏡頭完全由使用者操作。
- **暫離**：從跟隨／全隊因拖曳掉到自由，但還記得上一個對象，對應按鈕顯示外框，點了就回去。

## 目前三頁不一致的地方（2026-11-18）

| 頁面 | 使用者動了地圖之後 |
|---|---|
| 行程頁 | 暫停跟隨 12 秒，之後自動恢復原本的跟隨對象 |
| 回放 | 拖曳或滾輪直接把跟隨關掉（`setFollow('off')`），要自己再按 |
| 戰情室 | 暫停（`autoFollow = false`），要按「全隊」才恢復 |

已修好的前提（890e536）：手指／滑鼠按在地圖上時，跟隨不再每格 `jumpTo`（以前 `jumpTo` 會中止 MapLibre 正在辨識的手勢，跟隨中拖不動地圖）。

## 實作備註（給之後的人）

實作時另外決定的：
- 回放的「車頭朝上」：使用者一旋轉就停止轉方向（仍跟拍），重新點人才恢復。
- 跟隨中使用者自己拉遠，不再被「zoom < 12 就重飛」強制拉近；自動回去、點暫離中的同一個人回去時保留縮放。拖回放時間軸也保留縮放。
- 戰情室自動旋轉在使用者操作中（`M.busy`）暫停。
- 暫離樣式：工具鈕 `.tool.away`、隊員列 `.team-row.away`（accent 外框）。

原本的備註：

- **狀態機**：三頁共用一個 `camMode`：`follow:{uid}`／`group`／`free`，外加 `resume`（暫離前的模式）與 `resumeAt`。按鈕樣式只看這兩個值。
- **只有「位移」才斷開**：只聽 `dragstart`（且 `e.originalEvent` 存在，程式 `easeTo` 不算）。`zoomstart`／`rotatestart`／`pitchstart` 不再當「動了地圖」。目前三頁都把四種事件一起處理，要拆開。
- **以被跟隨的人為中心縮放**：MapLibre GL JS 可用 `map.scrollZoom.enable({around:'center'})`、`map.touchZoomRotate.enable({around:'center'})`，跟隨／全隊時開、自由時恢復預設（以手指／游標為中心）。人一直在畫面中心是因為 `follow()` 把他放在 center；有抽屜留白（`smoothPad`）時要確認 `around:'center'` 用的是加了 padding 的中心。
- **點兩下**：`doubleClickZoom` 以點擊位置為中心，跟隨時改成自己處理 `dblclick`：`easeTo({zoom: z+1})`（中心不動）。
- **雙指位移門檻（第 2 條）**：雙指時 MapLibre 的 `dragPan` 也會平移。跟隨中偵測到兩指時先忽略位移，兩指中點累計超過 60 px 才把它當拖曳（呼叫跟第 1 條同一個函式）。
- **單指門檻（第 1 條）**：MapLibre `dragPan` 本身有 `clickTolerance`（預設 3 px），10 px 門檻在 `dragstart` 後自己累計位移再判斷，門檻內仍跟隨（下一格會被拉回中心）。
- 全隊模式使用者縮放後，`followGroup` 不能再改 zoom（第 8 條轉暫離即可）。
- 手指／滑鼠按在地圖上時不 `jumpTo`（890e536 已做）沿用。

## 參考資料

找過沒有專門給網頁地圖做「跟隨＋手勢」的獨立開源套件，最接近的是各地圖 SDK 內建的定位跟隨元件：

- MapLibre Native Android `LocationComponentOptions`（開源）：`trackingGesturesManagement`、`trackingInitialMoveThreshold`、`trackingMultiFingerMoveThreshold` — https://maplibre.org/maplibre-native/android/api/-map-libre%20-native%20-android/org.maplibre.android.location/-location-component-options/-builder/tracking-gestures-management.html
- Mapbox Navigation SDK `NavigationCamera`（IDLE／FOLLOWING／OVERVIEW，手勢一律轉 IDLE）— https://docs.mapbox.com/android/navigation/api/coreframework/3.25.1/ui-maps/com.mapbox.navigation.ui.maps.camera/-navigation-camera/
- Mapbox Maps 進階 viewport 範例（跟隨時 `gestures.focalPoint` 設成定位點，捏合以人為中心）— https://docs.mapbox.com/android/maps/examples/android-view/advanced-viewport-with-gestures/ 、iOS：https://docs.mapbox.com/ios/maps/examples/viewport-advanced/
- MapLibre GL JS `GeolocateControl`（本專案已在用的函式庫；`ACTIVE_LOCK`／`BACKGROUND` 兩態與按鈕樣式）— https://maplibre.org/maplibre-gl-js/docs/API/classes/GeolocateControl/
- OsmAnd「自動置中地圖」秒數設定（開源導航 App）— https://docs.osmand.net/docs/user/navigation/guidance/map-during-navigation
- rnmapbox issue #3115（縮放就失去跟隨的常見抱怨）— https://github.com/rnmapbox/maps/issues/3115
