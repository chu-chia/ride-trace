## 2. 效能量測浮層（`web/assets/perf.js`）

- 開法：網址 `?perf=1`（`?perf=0` 關），或**設定頁 → 地圖 →「效能量測浮層」**（加到主畫面的 App 沒網址列，用這個）。存在 sessionStorage／localStorage，換頁保留。
- `common.js` 的 `PERF` 判斷要不要載入；`mapbase.js` 建好地圖後交給浮層（`window.__qijiMaps`）。
- 顯示最近 5 秒：FPS、1%low、最長一格、掉格比例、超過 50ms 次數、**地圖每秒重畫次數**、每格 JS 時間（包住 `requestAnimationFrame` 量）、每秒圖磚載入（依來源）、目前地圖解析度。
- 點一下換角落；長按 0.6 秒歸零。
- A/B 開關（`qiji:perf-flags`，localStorage，**會一直留著**，測完記得關）：遠處減細節（`setSourceTileLodParams(3.5, 2)`）、傾斜 45°、解析度 1.25、3D 20fps（頁面迴圈和地圖一起降）、只傾斜不地形、毛玻璃、關山影、不跟隨、不取高度、不更新軌跡。
- 讀數注意：**FPS 是瀏覽器格數（最高 60），地圖重畫才是地圖本身**；省電模式刻意限地圖 30 次/秒，所以手機上地圖最順就是 30。

## 3. 「很卡」的定義（和使用者確認過）

省電模式（目標 30 次/秒）下：**每 5 秒有 5 格以上超過 50ms**（約每秒頓一下）。
不用「重畫次數」判斷：隊伍停著時地圖本來就不用重畫，會誤判。太卡提醒（`mapbase.js watchSlow`）照這個標準，連續兩個 5 秒區間才算。

## 4. iPhone 實測數據（省電模式、充電中、Demo #57 與中橫 11/17 回放）

第一輪（改之前）：

| 頁面／情況 | FPS | 1%low | >50ms／5 秒 |
|---|---|---|---|
| 首頁 | 60 | 56 | 0 |
| 行程頁 全隊 3D | 58～60 | 29～38 | 0 |
| 行程頁 抽屜全開 | 57 | 27 | 1（地圖還在每秒畫 30 次） |
| 導航頁 | 60 | 40 | 0 |
| 戰情室 3D | 前 10 秒 60，之後 28～31 | 13～15 | 33～42 |
| 戰情室 2D | 60 | 42 | 0 |
| 回放 3D 播放 | 55 → 39 | 20～28 | 2 |

3D 卡頓的拆解（回放／戰情室）：
- 每格 JS 只花 2～4ms，格卻 33～55ms → **瓶頸在 GPU**；圖磚每秒只載 1～3 張，不是圖磚一直重抓。
- 不跟隨（鏡頭不動）一樣卡；同一時間切 2D 立刻 60 → 不是鏡頭移動、也不是發熱。
- 粗山影（dem-hs maxzoom 10／9）沒用：山影負擔在逐像素計算，不在圖磚數量。
- 戰情室最後一輪（判定用上面的標準）：

| 方案 | 地圖重畫 | >50ms／5 秒 | 判定 |
|---|---|---|---|
| 立體地形 | 22～23 | 20～27 | 卡 |
| 遠處減細節＋45°＋解析度 1.25 | 23～26 | 16～21 | 卡 |
| 3D 20fps | 20（刻意） | 8 | — |
| **只傾斜不地形** | **30** | **0** | 順 |
| 平面 2D | 30 | 0 | 順 |

改完後：
- 抽屜全開：地圖重畫 30 → **0**，1%low 27 → 56，掉格 15% → 0%。
- 回放只傾斜（解析度 2）：每秒 26～27 次、0 次頓挫。
- 毛玻璃（底色 45%、模糊 16px，右上 4 顆按鈕）：1%low 36 → 29～34，仍順。

參考的市面做法（給使用者看過）：Google 導航 SDK 導航中自動調幀率、省電降到 10 fps；Komoot 的 3D 地圖只在電腦版；Apple Maps 拉近會放平傾斜。

## 5. 改了哪些行為

- `mapbase.js`
  - `terrainPref()`／`TERRAIN_KEY`（`qiji:terrain`）：沒設定時 = 不是省電模式（電腦開、手機關）。
  - 3D 時只有偏好開才 `setTerrain`；否則只傾斜（立體建築、山影、天空照舊）。`M.useTerrain`、`M.setTerrainEnabled(on)`。
  - `mapDpr(withTerrain)`：省電且畫地形 1.5 倍，省電沒地形 2 倍，一般模式原生。
  - `pauseRender(on)`：包住 `triggerRepaint`，暫停期間只記 dirty，恢復時補畫一次。
  - `watchSlow()`／`askTilt()`：太卡提醒，sessionStorage `qiji:terrain-asked` 同分頁只問一次。
- `trip.js`：tick 裡面板上緣 < 畫面 25%（手機、非導航模式）就 `pauseRender(true)`，用實際位置判斷，拖曳一露出地圖就恢復。
- `war-m.js`：`setOff` 裡 `px <= 1 && animate`（全開而且不是拖曳中）就暫停。
- `common.js`：`frameGate` 支援 3D 20fps 開關；`toast(text, { action, ms })` 回傳元素、可放動作按鈕。
- `settings.html`：地圖區加「立體地形」「效能量測浮層」兩個開關。

## 6. 測試做法（這次新增）

- **iPhone 鏡像操作**：用 Python Quartz 找 `iPhone鏡像輸出` 視窗（`CGWindowListCopyWindowInfo`），截圖用 `screencapture -x -o -l <視窗號>`（得到 2 倍像素）。點擊＝滑鼠 down/up 事件（座標除以 2 加視窗原點）；**捲動要用滾輪事件**（`CGEventCreateScrollWheelEvent`），在文字上用滑鼠拖曳會變成選取文字；拖抽屜把手可以用滑鼠拖曳。腳本放在 scratchpad，沒有進版控。
- 鏡像的串流本身會卡，**不要看畫面判斷順不順，看浮層數字**（數字是手機自己算的）。
- 浮層蓋在左上角時會擋到東西，點錯會點穿到底下元素；換角落或先確認按鈕狀態（截圖放大看橘色）再量。
- 從戰情室按返回，瀏覽器可能把舊的行程頁從快取還原（舊程式、舊浮層），要回首頁再重新進。
- 測 3D 太卡提醒：Playwright 的 CDP `Emulation.setCPUThrottlingRate` 30 倍，約 20 秒內會跳提醒。
- 臨時 session 用 api 容器裡的 `REDIS_URL` 建（`docker compose exec -T api python -c "...redis.from_url(os.environ['REDIS_URL'])..."`），不用讀 `.env`；測完刪掉。這次的臨時 session 都刪了。
