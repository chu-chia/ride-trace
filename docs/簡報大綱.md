# 簡報大綱（約 16 頁）

依規格 0.2 要求的順序：動機與目標 → 參考 → 作品介紹（架構、流程、亮點）→ Redis 進階功能與 SQL 的比較 → 雲端網址 → 成果、心得、待解決問題。圖的來源標在每頁後面。

1. **封面**：騎跡 —— 整隊一起出發，一個都不少。學號、姓名。（背景用登入頁的路線巡航截圖）
2. **動機**：跟朋友騎山路，最常發生的事：有人落隊沒人知道、在岔路走散、到了集合點不知道誰還沒到、回家後想看整趟卻只有各自的紀錄。
3. **目標**：手機即時看到全隊 → 自動警示 → 整趟回放 → 長期紀錄（全年足跡、點亮鄉鎮）。不做速度排行，避免鼓勵飆車。
4. **為什麼選 Redis**：位置每 2～3 秒一筆、要即時推給全隊、要地理查詢、要時間序列 —— 正好是 Redis 的強項。
5. **系統架構**：`docs/架構與UML.md` 第 1 節（手機 → API → Redis → Worker、Pub/Sub → 瀏覽器；本機 Valhalla）
6. **一筆位置回報發生了什麼**：第 4 節循序圖。重點：一個 Pipeline 十幾個指令一次送出；Pub/Sub 即時；Streams 交給 Worker。
7. **Worker 與 Consumer Group**：兩個 group 各拿一份、同 group 多個 worker 分攤；XACK、XAUTOCLAIM 接手當掉的；Lua 依 ts 去重（at-least-once）。後台截圖：每秒寫入、lag 0。
8. **警示**：落隊（沿路線里程中位數，髮夾彎例子：直線 400 m、沿路線 3 km）、失聯（TTL＋Keyspace Notification）、抵達與全員到齊（SADD＋SDIFF＋SET NX）、異常久停、偏離路線（HSETNX）。第 6 節活動圖。
9. **互動**：Web Push 推播（第三個 consumer group `push`、SET NX 去重）、聊天室（Stream＋Lua 已讀指標、XREVRANGE 翻頁）、快速訊息（SET NX PX 限流）、標註與前方坑洞提醒（GEOSEARCH 扇形）、SOS（長按、全隊紅色橫幅）。截圖：行程頁＋SOS。
10. **導航與規劃**：搜尋地點（RediSearch 中文＋FT.SUGGET 自動完成）、機車／重機／汽車路權（國道、快速道路、國道3甲例外）、3 個方案、依你的速度（TS.MRANGE GROUPBY）、沿路線找加油站（Pipeline 上百個 GEOSEARCH）、路線存 RedisJSON。截圖：規劃頁。
11. **回放**：Streams XRANGE＋TS.MRANGE 一次取全隊速度海拔、事件時間軸、跟拍鏡頭。截圖：回放頁。
12. **長期紀錄**：全年足跡（Set SUNION 迷霧）、點亮 368 鄉鎮（GEOSHAPE CONTAINS）、熱力圖（ZINCRBY）。截圖：我的紀錄三分頁。
13. **戰情室與後台**：大螢幕截圖；後台的 key 型別分布、每秒寫入／Pub/Sub。
14. **Redis 解決了哪些 SQL 不方便的事**（表格）：
    - 即時推播 → SQL 要輪詢；Redis Pub/Sub 一推就到
    - 「離我最近的隊友」「800 m 內的加油站」「這個點在哪個鄉鎮」→ SQL 要 PostGIS；Redis GEO／GEOSHAPE 內建
    - 每秒幾十筆位置寫入 → Pipeline＋Streams，寫入 O(1)
    - 時間序列降採樣、依標籤聚合 → TimeSeries MRANGE GROUPBY
    - 「只警示一次」「全員到齊」這種競爭條件 → Lua／NX 原子判斷，不用鎖表
    - 幾千個座標的路線只取摘要 → RedisJSON 路徑查詢
    - 外部 API 每月只有 3 點 → cache-aside＋TTL、SET NX 鎖防 stampede、RENAME 原子換資料（TDX 前方路況）
15. **雲端網址與展示**：Tailscale Funnel 網址、QR code；GitHub。
16. **成果、心得、待解決**：用真實一年 GPX（16.5 萬點、353 天）＋公開資料；心得（MapLibre 標記定位的坑、Valhalla 估時太樂觀改用個人速度）；待解決：天氣（氣象署）、手機背景定位只能靠 Traccar。
